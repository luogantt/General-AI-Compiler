上半部分回答“为什么要有这些步骤”，下半部分回答“代码里谁指向谁”。 先看逻辑，再看拓扑；两者说的是同一件事。

二、模块拓扑：代码里谁指向谁

这张图只画模块之间的实际依赖。实线是必经的数据/控制流，虚线是汇总或旁路， 双向箭头表示“选择 + 返回发射结果”。每个框里都写了这个模块在做什么。

入口 合法性 / 预扫描 规划 Kernel 发射 目标 ABI 产物 / 公共 API 必经数据/控制流 汇总 / 旁路
  • 00 → 01 / 02：模块和配置进入合法性与 LayerNorm 预扫描。
  • 01 → 03：只有合法的静态图才能进入 Buffer 规划。
  • 02 → 04：预扫描只把 LayerNorm 的 ownership 交给 Dispatch 循环。
  • 03 → 04：Buffer 规划把 allocations 交给 Dispatch 循环，后者才知道指针。
  • 04 ↔ 05：Dispatch 选择实现；发射器返回 Kernel body。
  • 05 → 06：Kernel body 加上目标 ABI，成为可调用的设备函数。
  • 04 → 07 / 06 → 07：Dispatch 元数据和 ABI 字段进入 Manifest。
  • 03 → 07（虚线）：allocation 表直接进入 Manifest 的 tensor 表。
  • 06 → 08（虚线）：target IR 进入 LLVM 转换，最终生成 PTX / vxbin。

三、两层怎么对应

上面六个逻辑步骤，落到代码里就是下面这些模块。看懂对应关系，就不会把“模块”和“步骤”混在一起。

合法性谓词 → 01 + 02

01 检查通用算子/形态；02 只处理 Triton LayerNorm 的完整闭包。

DAG 线性化 → 04

Dispatch 循环把每个输出值的生产者变成一条 dispatch，并记录 depends_on。

生命周期内存分配 → 03

Buffer 规划负责 TensorAllocation、view elision、last-use 和 64B arena。

实现选择 → 04 + 05

04 做选择，05 是四类实际发射实现；二者通过双向箭头连接。

Kernel 构造 → 05 + 06

05 生成函数体；06 套上 CUDA/Vortex 调用约定和指针 ABI。

合同序列化 → 07 + 08

07 写 plan.json；08 把 device IR 收敛到 LLVM，最终生成机器码。

四、用一张小图走完

`%A + %B → ReLU` 是能覆盖全部六个步骤的最小例子。 

%A = input  tensor<4xf32>
%B = input  tensor<4xf32>

%T = gac.add   %A, %B   // dispatch 0
%Y = gac.relu  %T       // dispatch 1

return %Y
  1. 合法性：add/relu 都在白名单；shape 静态 4；FP32。通过。
  2. 线性化：dispatch 0 输出 %T；dispatch 1 输出 %Y，依赖 0。
  3. 内存：%A/%B 是输入 Buffer；%T arena offset 0；%Y offset 64，活到结束。
  4. 选择：add/relu 是规则逐元素算子，默认 Linalg pointwise，也可 legacy 标量。
  5. Kernel：add_kernel(ptrA, ptrB, ptrT)、relu_kernel(ptrT, ptrY)；每线程一个元素。
  6. 合同：manifest 记录两个 offset、dispatch 顺序和依赖；Runtime 依次启动。

五、几个容易搞反的点

  • 不是一个大 Kernel。每个输出张量一个 dispatch；Kernel 之间用全局 Buffer 交接。
  • 不是运行时 malloc。所有 offset 编译期确定；Runtime 只按 manifest 映射地址。
  • 不是所有算子同一条路径。规则 Linalg、专用标量、设备模板、Triton 是四种 Kernel 来源。
  • 不是 manifest 只是日志。它是 Runtime 唯一执行合同，并且会被重新校验。
  • 不是先选模板再分内存。Buffer 生命周期和实现选择解耦；模板/Triton 不改变 Buffer 规划。
  • 不是失败就换后端。选择失败保留 native 标量路径并记录原因，不静默切换。
一句话总结：DeviceLowering 把“张量图”变成“一串带指针和线程号的 Kernel + 一张全局内存地图 + 一份 Runtime 能执行的合同”。 代码位置以当前工作树为准。
