ONNX 前端怎样提取 Graph IR？

沿着同一个小模型，逐步看清：读哪个字段 → 做什么转换 → 保存到哪个变量 → 交给哪个接口。

模型文件 .onnx→ONNX ModelProto→GAC Graph（Python 对象）→优化 / 后端生成 MLIR→工具链与 Runtime

ONNX 本身已有计算图。这里的“提取 IR”，是解析已有图并转换成项目自己的表示。前端不会执行一次模型推理来获取每层结果。

先看文件里有什么

ONNX（Open Neural Network Exchange）定义模型交换格式和算子语义。常见 .onnx 文件是 Protocol Buffers 二进制数据；读取后成为 ModelProto 对象。

ModelProto：模型外壳ir_version / opset_import / graphIR 版本描述格式；opset 描述算子语义版本。两者不是同一个版本号。
GraphProto：计算关系node / input / output / value_info节点、输入输出接口，以及已知的中间张量类型。
TensorProto：常量数值initializer / Constant.value权重、bias、shape 参数等。大权重也可能在外置文件中，由模型记录位置。
文件里的三种内容要分开：“做什么”由节点描述；“张量多大、什么类型”由类型信息描述；“权重具体是多少”由常量数据保存。输入图像和一般中间激活的实际数值，要在运行时才出现。

格式依据：ONNX Concepts · ONNX IR 规范。ONNX 还允许函数、子图等结构；当前 GAC 前端对尚未支持的结构会报错。

提取出来的东西，究竟放在哪里？


load_onnx(path) → Graph 是内存接口。调用返回时，数据主要在 Host 进程内存里，尚未分配 Vortex DDR / LMEM。


Graph 字段本例内容实际用途


graph.inputs["X"]TensorSpec((1, 2), "float32")规定调用者需提供什么输入；不保存 X 的数值。


graph.constants["W"]2×2 的 NumPy 数组保存权重真实数值；b 同样在 constants 中。


graph.nodes[0]MatMul(inputs=("X", "W"), outputs=("M",))通过名字引用数据，表达运算关系。


graph.value_specs["M"]shape=(1,2), dtype=float32后端据此推导循环和存储需求；不是 M 的计算结果。


graph.outputs("Y",)声明最终返回哪些张量。


graph.metadata来源、opset、转换统计、未支持原因追踪来源并做支持分析。




例如读取一个 MatMul：node.inputs[1] == "W" → 查找 graph.constants["W"] → 得到真实权重数组。节点间连线也是同一个原则：上游的输出名 M，就是下游 Add 的输入名 M。

Graph→后端生成 .mlir→显式调用 mlir-opt→LLVM IR / VOLT→ELF / vxbin→Runtime


上面最后一条是 Vortex 的后续工具链。前端不直接把 Python Graph 交给 mlir-opt，也不在 ONNX 导入时加载 MLIR 动态库。设备权重搬运由 artifact 与 Runtime 路径处理。

源 ONNX导入后的 Graph如何理解


Constant 可移入常量表；一个源节点也可能展开为多个节点。节点数变化不等于融合加速。


constants 除了权重，还包含从节点中提取或在转换中生成的常量。




这份真实图目前是检查模式结果。2,996 个节点仍保留 ONNX 限定名，8 个中间输出尚无完整类型。严格导入在位置编码 Expand 的 shape 非编译期常量处失败，不能直接把这份诊断 Graph 送入后端就声称完成全模型编译。
