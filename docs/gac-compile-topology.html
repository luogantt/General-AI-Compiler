GAC NATIVE COMPILER / DRIVER RESPONSIBILITY

gac-compile.cpp 到底负责什么？

先区分“总控代码”和“实际算法”：这个 main() 负责调用谁、先后顺序和停止位置；ONNX 导入与各种 IR 改写由它调用的其他 C++ 文件实现。

一句话：OnnxImporter.cpp 把 ONNX 变成内存中的 MLIR ModuleOp；gac-compile.cpp 接住它、按参数运行后续 Pass，最后把结果写出去。

先只看职责：gac-compile.cpp 是流程组织者

OnnxImporter.cpp 已经完成 ONNX → MLIR。随后 gac-compile.cpp 拿到这个 MLIR 对象，决定再调用哪些 Pass、按什么顺序调用，以及最后输出哪一层 IR。

到这里 main() 结束。只有输出 LLVM Dialect 后，外部工具才继续生成 LLVM IR 和机器程序。

关键点：OnnxImporter.cpp 的直接输出是 func.func + gac.conv2d / gac.matmul / gac.softmax ...，不是 Linalg。只有显式继续走 Linalg 路线时，gac-compile.cpp 才调用 createLowerRegularToLinalgPass()。默认流程在高层图优化后就停止。
