当前已验证：GAC 的 Vortex 路径是静态 FP32 FFN：FC1 / Bias / ReLU → FC2 / Bias / Residual → LayerNorm。两个 GEMM 支持 DXA + LMEM 双 Buffer，设备端由 MLIR 经 LLVM IR、VOLT 生成机器码。

计算模板在这里：算子映射之后，具体分块与调度之前

后端算子映射→→Tiling：填写块尺寸→Schedule：安排时序→Codegen：生成指令

模板确定计算结构、数据复用方式、累加位置和所需 Buffer；Tiling 将 BM/BN/BK 等参数具体化；Schedule 决定线程分工、搬运、计算与同步时机。资源或精度不满足时，这三个决策需要一起调整。

先产生合同，运行时才按合同搬数据

这十个模块是职责划分，并不要求实现为十个独立 Pass。合法化和子图切分确定目标支持范围；后端映射后选择计算模板，再实例化 Tile 与 Schedule。最终设备 Lowering 在这些决策确定后落地；资源或精度不满足时，要返回前面重新选择。

模板是编译器可参数化的计算结构，生成循环、Buffer 访问和目标操作。它没有独立的硬件存储位置；实际 SRAM 地址由模板参数及内存规划确定。VOLT 再把生成的设备 IR 变成机器指令。

机器码 / Kernel 入口 + 权重 + Shape / dtype / layout
Tile / 线程映射 + Buffer 大小与偏移 + DMA 描述符

编译器写下“读哪些地址、用哪个 Buffer、等谁完成、怎么算、写到哪里”。Runtime 分配地址并提交任务；硬件执行 load、store、搬运和计算指令。编译期的地址计划本身不装数据。

用 V3 的 4×4 矩阵，算清一个 2×2 输出块

纯 GEMM 示例：C=A×B，BM=BN=BK=2。一组 CTA 有 4 个逻辑线程，各算 C Tile 的一个元素。FFN 的实际累加器还包含 Bias，FC1 最后做 ReLU，FC2 最后加 Residual。

Device DDR→DXA 搬运→LMEM 内 A/B Buffer→操作数寄存器 / FPU→C 累加值→LSU / Cache / DDR

完整 A、B 留在 DDR；框表示地址范围，不是物理切开矩阵。

A[4,4] · M×K

B[4,4] · K×N

② LMEM 物理 SRAM · 本 CTA 64 B

Buffer 是 SRAM 内的地址区；每组 Stage 同时保存 A Tile 和 B Tile。

Stage 0：+0…15 B   A Tile
         +16…31 B  B Tile
Stage 1：+32…47 B  A Tile
         +48…63 B  B Tile

Buffer 切换只改变读写偏移，不把数据复制到另一块 SRAM。当前输入读完，才能覆盖同一地址区。

③ 每线程的 C 累加值

一共 4 个输出元素。IR 中是跨 K 循环的 SSA 值，VOLT 负责寄存器分配。

A/B Buffer 缓存输入。乘积加到 Cacc，最终 C 经 global store 写出，不必先放回 A/B Buffer。

4 个逻辑线程不等于保证同一时钟有 4 个物理加法器同时完成；吞吐还取决于 lane、FPU、发射宽度与流水线。

轴顺序、物理布局与 SRAM bank 是三件不同的事

轴顺序决定先迭代哪一维，layout 决定同一个元素位于哪个地址，bank 映射决定访问落到哪个物理存储组。编译器改变布局后，搬运的目的索引和计算的读取索引必须一起变化。

位置 / 决策本例规则影响
输出分工与 K 循环CTA 按 M/N 选 C Tile；每线程沿 K 累加K 分块后不清空 Cacc；完成全部 K 才写出
DDR row-major 地址A[row,k] 的行步长为 K；B[k,col] 的行步长为 NDDR stride 来自完整矩阵，不是 BK 或 BN
LMEM 紧凑 Tile 布局A[local_row,j] 的步长为 BK；B[j,local_col] 的步长为 BNDMA 会把有 DDR stride 的窗口搬成紧凑 Tile
4-bank 教学例子bank = word_index mod 4；索引单位是 32-bit word不同地址 [0,4,8,12] 都落 bank 0；[0,5,10,15] 分散到四 bank

padding / swizzle 可改变冲突，但增加容量或地址计算。相同地址是否广播取决于硬件。Vortex bank 选择与端口仲裁可对照 VX_local_mem.sv；本例 bank 规则不是所有 NPU 的统一规则。

改变 Tile，观察容量约束与搬运/计算模型

FP32 教学模型：SRAM 16 KiB、示意预留 2 KiB、总 K=256。算力 256 GFLOP/s、有效带宽 16 GB/s 均为假设，非 Vortex 实测规格；预留量不是固定硬件规定。

SRAM 容量只是一条约束，还要检查线程、寄存器、barrier、bank 冲突与并发。填满 SRAM 不会自动发生系统 swap；寄存器溢出可能产生 spill，Buffer 不够则需换 Tile、分阶段或显式 DDR 溢出方案。

瓶颈分析要形成反馈闭环

观察到什么如何确认修改什么
DMA / memory stall 高，计算单元等待看 DDR 字节数、有效带宽、搬运完成事件与 FPU 利用率减少重复读、合并访问、增加 Tile 复用，验证双 Buffer 是否真的重叠
LMEM 容量够，但 load 等待多看 bank 冲突、访问步长、队列争用修改布局、padding、swizzle 或线程映射；不能只扩大 Buffer
Tile 更大却更慢检查寄存器、spill、驻留 CTA 数、尾块浪费、同步开销缩小 Tile 或更换每线程计算量，比较同 Shape 的完整运行
Kernel 快，但端到端仍慢拆分 H2D、launch、kernel、跨子图转换、D2H减少边界搬运和启动，保留常驻权重，重新评估子图切分

实测参照：当前合成 FFN 的 [1,8,256]→512→256 使用 4×4×128，SimX 总周期由 74,031,533 降至 61,048,712（减少 17.5%）；小尺寸可能更慢。这不是完整模型或真机延迟。
